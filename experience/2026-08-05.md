1. ctypes `OpenProcess(0x0410)` + `VirtualQueryEx`/`ReadProcessMemory` 遍历 32 位进程全部 COMMIT 可读区
2. 以表头 `#iTalenID\tsTalenName\tsTalenTip\tsTalentimage\tiType` 为锚点定位

4. 严格 `utf-8` 解码（出现 `\ufffd` 说明抠错）

### 【严重修正 08:25】存档绝对不能带 UTF-8 BOM —— 会导致该档无法读取
用户反馈 **Save18 进不去了**。根因不是天赋 354，而是我写存档时加了 BOM：

```
日志第227行  JsonReaderException: Unexpected character encountered while parsing value: ﻿
                                  Path '', line 0, position 0
坏档  head = ef bb bf 7b   size 501382   ← 我写的（多3字节）
原版  head = 7b 22 6d 5f   size 501379   ← 游戏自己写的，即 `{"m_`
```

- 游戏读档是 `bytes → Encoding.UTF8.GetString() → Json.NET 反序列化`，
  **不走 `File.ReadAllText`，BOM 不会被自动剥离**，U+FEFF 残留在首字符 ⇒ JsonReaderException
- 当时看到"多 3 字节"误判成"BOM 计算差"而放过，教训：**存档字节数必须与原档完全一致**

**正确做法：字节级最小替换，绝不整体重新序列化**
1. 以游戏自己写的原档为基准读 `bytes`，`decode('utf-8')`（不是 utf-8-sig）
2. 用 `iNpcID` 锚点定位窗口，正则找到目标 `"TalentList":[305,` 精确替换首个数字
3. `encode('utf-8')` 直接写回，**不加 BOM**
4. 断言三件事：`len(new)==len(old)`、`new[:3]!=b'\xef\xbb\xbf'`、字节差异数 ≤3
   本例结果：长度差 0，字节差异 2 处 @ offset 61130/61131（`'0'→'5'`, `'5'→'4'`）
5. 再做递归语义 diff 确认差异数 == 1

> 整体 `json.dumps` 重序列化风险大（BOM、浮点格式、键序、分隔符都可能变），
> **能做字节替换就不要重序列化**。

**排查存档问题的第一动作**：看 `output_log.txt` 里的 `JsonReaderException`，
并用 `head 前4字节` 与同目录其他存档对比（正常应为 `7b226d5f`）。
